Method Lab

"Try in this order" 목록에서 무엇을 아래로 내릴지 비교합니다. 상황은 모두 같습니다: OpenAI 에 Plan login(켜짐, 로그인), Plan login 2(켜짐, 로그아웃), API key(꺼짐), API key 2(꺼짐, 키 있음).

M0. 기준

지금. 켜진 것 먼저, 꺼진 것은 그 아래에 이어서. 줄 끝에 On/Off 글과 스위치가 둘 다 있고, 추가 줄 둘이 목록 끝에 붙어 있습니다.

M1. 꺼진 수단을 아래 묶음으로

켜진 수단만 "Try in this order" 에 번호와 함께. 꺼진 수단은 맨 아래 "Off" 묶음으로 내려가 번호도 순서 버튼도 없습니다. 스위치를 켜면 위 목록 끝으로 올라갑니다. 시도되지 않는다는 것이 자리로 드러납니다.

M2. 상태 글을 없애고 스위치가 상태

On/Off 글과 스위치가 같은 말을 두 번 하므로 글을 뺍니다. 쓸 수 없는 이유(로그아웃, 키 없음)만 작은 배지로 남깁니다. 줄이 가장 짧습니다.

M3. 상태를 이름 아래 줄로

이름 아래 작은 회색 줄에 상태와 계정. 두 줄 행이 되어 길어지지만, 오른쪽 끝은 순서 버튼과 스위치만 남아 정돈됩니다.

M4. 추가 버튼을 맨 아래 하나로

"+ Plan login", "+ API key" 두 줄 대신 섹션 맨 아래 "+ Add" 하나. 누르면 작은 메뉴에서 종류를 고릅니다. 목록과 추가 동작이 시각적으로 분리됩니다.

M5. 종류별 묶음 + 꺼진 것 아래

순서 목록은 켜진 것만 하나로 두고, 아래에 "Plan logins", "API keys" 종류별 보관함. 보관함의 각 묶음 끝에 추가 줄. 계정이 많아질 때 관리가 쉽습니다.

공통

  • 켜진 수단만 시도되고, 순서는 위에서 아래
  • 초록 점 = 지금 쓸 수 있음(켜짐 + 로그인/키 있음)
  • 꺼진 수단은 순서 버튼이 없거나 막힘

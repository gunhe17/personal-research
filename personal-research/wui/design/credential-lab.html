Credential Lab

한 제공사에 플랜 로그인과 API 키를 둘 다 등록해 두었을 때, 어느 쪽을 먼저 쓰고 언제 다른 쪽으로 넘어갈지 정하는 화면을 비교합니다. 모든 시안은 같은 상황입니다: OpenAI 플랜은 로그인됨, API 키 …9f2c 도 저장됨. 제목 아래에는 상태만 둡니다.

C0. 기준

둘 중 하나만

지금의 화면. 고른 쪽만 쓰고, 다른 쪽은 저장돼 있어도 보이지 않습니다. 플랜 한도에 걸리면 답변이 실패합니다.

C1. 순서 목록

위에서부터 시도 · 화살표로 순서 바꿈

등록한 인증 수단을 번호 목록으로. 1번이 실패하면 2번으로 넘어갑니다. 각 줄에 상태와 관리 동작이 함께 있어 "무엇이 등록됐고 어떤 순서인지"가 한 덩어리로 읽힙니다.

C2. 기본 + 대체 스위치

지금 구조에 스위치 하나

지금처럼 하나를 기본으로 고르고, 아래에 "실패하면 다른 쪽으로" 스위치. 켜면 언제 넘어갈지 조건 셋이 나타납니다. 지금 화면에서 가장 적게 바뀝니다.

C3. 방식 네 갈래

세그먼트 하나로 끝 · 흐름 그림

플랜만, 플랜 → 키, 키 → 플랜, 키만. 고른 방식을 아래에 화살표 흐름으로 그려 결과를 바로 보여 줍니다. 인증 수단 관리는 그 아래 두 줄.

C4. 인증 카드 둘

나란히 · 배지로 역할

플랜과 키를 같은 크기 카드로 나란히. 카드 머리에 Primary / Fallback 배지, 바닥에 "Use first" 버튼. 둘이 대등한 수단이라는 점이 가장 잘 드러납니다.

C5. 용도별 배정

답변 · 번역 · 수집 정리마다

우선순위를 용도마다 따로. 대화 답변은 플랜, 긴 번역은 키처럼 나눕니다. 번역이 플랜 한도를 다 쓰는 일을 막을 수 있지만 칸이 많아집니다.

C6. 대체 + 비용 한도

llm 기록에서 이번 달 사용량

플랜 우선, 키로 대체. 대신 키에는 이번 달 한도를 둡니다. llm 표의 호출 기록으로 사용량 막대를 그리고, 한도에 닿으면 대체를 멈춥니다. 키 과금이 걱정될 때.

동작 규칙 (모든 시안 공통)

  • 대체는 한 번만: 첫 수단이 실패하면 다음 수단으로 같은 요청을 다시 보냄
  • 넘어가는 조건: 사용 한도(rate limit), 로그인 만료, 실행 실패. 응답 형식 오류는 넘어가지 않음
  • 어느 수단으로 답했는지는 답변 머리에 작게 표시(예: "GPT-6-Astra · API key")하고 llm 기록에도 남김
  • 등록 안 된 수단은 순서에 있어도 건너뜀. 아무것도 없으면 Sign in needed

# 체인지로그

Unified Harness Protocol에 대한 모든 주목할 만한 변경 사항.

## 2026-08-11 — 첫 공개 버전

이 명세는 추상적으로 설계된 것이 아니라, 실제로 배포 중인 HarnessRouter 구현에서 추출한 최초 명세입니다. 여기서 설명하는 모든 엔드포인트와 이벤트는 명세로 적히기 전에 이미 프로덕션에서 동작하고 있었습니다. 작업은 그 계약을 정확하게 문서화하고, 문서화하면서 드러난 공백을 메우고, 그 결과를 테스트 가능하게 만드는 것이었습니다.

### 정의된 것

- **아키텍처** — 클라이언트/서버/하네스 역할, 세 가지 준수 등급(Core, Extended, Full), 여섯 객체 모델, 전송과 인증.
- **생명주기** — `UHP-Version` 협상, 발견 문서 `GET /v1/uhp`, 태스크 상태(`in_progress`, `completed`, `failed`, `incomplete`, `cancelled`), 세션 생명주기, 동시성 규칙.
- **하네스** — 발견, 하네스 객체, 모델 카탈로그, 계산된 `available`, 그리고 Full 등급에서의 하네스 관리.
- **태스크** — `POST /v1/responses`, 응답 객체, `metadata.harness_id` 를 통한 하네스 선택, 모델 대체 보고, 아이덤포턴시.
- **스트리밍** — SSE 이벤트 어휘, `sequence_number` 순서 보장, 재연결.
- **세션** — `previous_response_id` 를 통한 이어가기, 목록 조회, 조회, 취소, 공유.
- **파일** — 인라인 입력과 업로드 입력, 산출물 주석, 다운로드, 미리보기, 보존.
- **오류** — 단일 오류 봉투, 폐쇄된 코드 집합, 재시도 규칙.

### 참조 구현에서 메운 공백

명세를 작성하는 과정에서 구현에 정의된 동작이 없던 세 곳이 드러났습니다.

- **역량 발견이 없었음.** 클라이언트는 서버가 무엇을 지원하는지 추측하거나 404 로부터 알아내야 했습니다. `GET /v1/uhp` 를 추가했습니다.
- **전송상에 프로토콜 버전이 없었음.** 응답이 어느 계약으로 작성됐는지 식별할 방법이 없었습니다. 모든 응답에 `UHP-Version` 헤더를 추가했습니다.
- **비정형 오류.** 실패가 단순한 사람이 읽을 문자열로만 반환되어, 클라이언트는 재시도 여부를 판단하려면 그 문구를 매칭해야 했습니다. 구조화된 오류 봉투를 추가했고, 기존 클라이언트가 계속 동작하도록 이전 문자열은 지원 종료된 별칭으로 남겨두었습니다.

### 알려진 타협

[VERSIONING.md](https://github.com/HarnessRouter/harnessrouter/blob/main/protocol/VERSIONING.md#the-current-versions-known-compromises) 에 기록되어 있습니다. 태스크와 하네스 표면 사이에 섞여 있는 필드 대소문자 표기, 그리고 `/v1/traces/{id}` 에 위치한 세션 삭제입니다. 둘 다 호환성을 위해 유지되며 향후 메이저 버전을 위한 표시가 되어 있습니다.
